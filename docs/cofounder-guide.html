1. How this all works (the 60-second mental model)

Think of the website as a restaurant. The kitchen is the developers writing code. The menu is the content (products, stories, prices). The dining room is Vercel — the platform that serves the site to visitors. Code in the kitchen becomes a new menu becomes a meal in front of a guest.

In slightly more technical terms:

  1. The developer writes code in a folder on their Mac (the local copy).
  2. They push that code to a website called GitHub (a safe, versioned storage for code).
  3. A platform called Vercel is watching GitHub. Whenever new code lands, Vercel automatically builds a fresh version of the website and puts it on the internet.
  4. The data — products, stories, prices, leads — lives in MongoDB (a database) and is edited through Payload (an admin dashboard at /admin).
Key takeaway: pushing code = updating the site. There is no "publish" button. Vercel listens and reacts.

3. How to see the site on your Mac

Sometimes you want to see changes before they go public — or poke at the site when the internet is acting up. The site runs locally on your Mac. You don't need to do this often — most of the time you'll just look at the live URL.

If you do want to run it locally:

  1. Open the Terminal app (Cmd+Space, type "Terminal", Enter).
  2. Tell the developer you want to "run locally" — they'll set it up the first time. After that, you only need:
cd ~/WORK/mithai-shop/mithai-shop
npm run dev
  1. Open a browser at http://localhost:3000.
  2. Press Ctrl + C in Terminal to stop.
Heads up: the local site is just for you. Customers cannot see it. Anything you do here does not affect production unless code is pushed.

4. How to ask for a change

As a non-tech co-founder, your main contribution is direction. The developer writes the code. Here's how to make requests that get done fast:

Good request

"On the home page hero, change the headline from 'Mithai, the modern way' to 'Mithai, made fresh daily.' Also, the 'Build a gift' button should open the wedding configurator instead."

→ Clear, names the page, names the element, names the desired behavior.

Frustrating request

"The home page feels off. Make it pop more."

→ Subjective, no clear end state. Will go in circles.

Best practices

  • One change per request. Bundling 5 changes into one message means one of them gets lost.
  • Reference the URL. "On /mithai…", "On the wedding configurator…".
  • Say what you want, not how. The developer picks the implementation.
  • Provide copy as final text. Don't make the developer guess wording.
  • Share screenshots or sketches for visual changes.

5. How to see a change go live

Once the developer picks up your request, here is what happens — and how you can watch:

1 Developer opens a PR

You get a link in GitHub (or Slack) that looks like github.com/org/repo/pull/42.

This PR page shows: what changed, comments, and a preview URL from Vercel.

2 Vercel builds a preview

Within ~2 minutes, the Vercel bot will comment on the PR with a preview URL like:

https://mishran-git-fix-headline-yourorg.vercel.app

Open it. This is exactly what the change will look like when live. Share with anyone for review.

3 Approve and merge

If happy: click "Merge pull request" on GitHub. (Or ask the developer to.)

Vercel now builds main → production is live in another ~2 minutes.

4 Verify on production

Visit the canonical domain (https://mishran.shop or whatever it is). Hard-refresh (Cmd+Shift+R) to bust caches.

6. How to edit content yourself (no code)

Most content — products, stories, prices, occasions — does not need a code change. You can edit it directly through the Payload admin dashboard.

  1. Go to https://mishran.shop/admin (or your domain + /admin).
  2. Log in with your admin account (developer will create one for you the first time).
  3. Pick the collection you want to edit: Mithai Products, Stories, Brand Settings, etc.
  4. Edit fields, click Save.
Beautiful thing: saving in Payload instantly updates the live site (within 60 seconds). No rebuild required.

What's safe to edit

  • Products — name, price, description, images, slug
  • Stories — title, body, pillar, hero image
  • Brand settings — tagline, positioning, contact details
  • Occasions, Karigars, Farms, Packaging — full CRUD
  • Analytics settings — GA4 ID, Meta Pixel ID, WhatsApp number

What needs a developer

  • New collection types (e.g., "Recipes" section)
  • New pages (e.g., a "/press" page)
  • Theme or layout changes
  • Anything that involves the URL structure

7. What to do when something breaks

The site is down

  1. Check https://www.vercel-status.com — is Vercel having an outage?
  2. If Vercel is fine, ping the developer. Do not try to fix it yourself.

The site is up but a page shows an error

  1. Note the URL and what you were doing.
  2. Take a screenshot.
  3. Send to the developer with the URL + screenshot + "what I expected" + "what I saw."

A change went live that shouldn't have

  1. Tell the developer immediately. Vercel has one-click rollback to the previous deploy.
  2. Do not panic-edit content to "fix" it — that creates a worse mess.

Orders or leads not coming through

  1. Contact the developer first with: who tried to submit, when, what form (wedding / corporate / contact).
  2. If you have Payload admin access (it requires secure auth — never share credentials), you can read the Leads collection to see if recent submissions arrived. Do not edit or delete records — report what you see to the developer.
  3. If submissions are in /admin but no email arrived: the email provider (Resend) is the suspect. Developer needs to inspect logs.
  4. If submissions are missing entirely: the form submission itself is broken. Developer needs to inspect.

8. FAQ

How long should a "small change" take?

For a text or color change: ~10 minutes of dev time + ~4 minutes of build time. For a layout change: half a day to a full day. For a new feature: days to weeks.

Why does it take 2 minutes for changes to appear?

Vercel has to rebuild the site from the new code. Think of it like printing a book — even if you only fixed a typo, you still have to wait for the printer to finish.

Can I edit the website from my phone?

Content yes (use the /admin dashboard in mobile browser). Code no.

What if I want to try a change without breaking anything?

That's what preview deploys are for. Ask the developer to put it on a branch — you'll get a private preview URL that customers can't see.

How do I add a new product?

Via /admin → Mithai Products → "Create New". No code needed. The product shows up on the site within 60 seconds.

What is "the cloud"?

Someone else's computer. In our case, Vercel's servers (which run our website) and MongoDB Atlas's servers (which run our database). Both are secure, professionally managed services.

Who pays for Vercel and MongoDB?

Right now, both have generous free tiers that cover early traffic. We'll upgrade only when usage demands it.

Can customers break the site?

Almost never. The site only "reads" content publicly — customers can't write to the database. The only inputs they have are lead forms, which are validated and sanitized.

How do I learn more about how this works?

Read the Current Functionality README (more technical) and the Developer Workflow (how changes ship). Both written for humans.
