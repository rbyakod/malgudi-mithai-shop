Publish Mishran to the Ubuntu VPS at mishran.roohib.com

Self-hosted deployment of the Next.js 16 + Payload CMS 3.87 storefront: local MongoDB on the VPS, app under systemd, Nginx reverse proxy, Let's Encrypt HTTPS. Everything below was checked against the actual repo configuration — env var names, the Mongo replica-set requirement, the pnpm workspace build, and media storage location.

01 · Before touching the server

Inputs needed

Access

  • SSH user for 2.24.221.70 (root or a sudo user).
  • DNS control for roohib.com (A-record creation).
  • GitHub access to rbyakod/malgudi-mithai-shop if cloning (repo is private — a PAT or SSH deploy key, see step 05).

Server

  • ≥ 2 GB RAM (or add swap — next build is memory-hungry; see troubleshooting).
  • Ports 80/443 open; outbound HTTPS allowed (build + seed fetch images from CDNs).
  • Nginx may already be installed — rerunning installs is harmless.

Secrets to generate

  • PAYLOAD_SECRET — openssl rand -hex 32
  • REVALIDATE_SECRET — another openssl rand -hex 32
  • Mongo app-user password (strong).

Licensing caveat. The golden seed data contains scraped product copy and storefront images for testing only. Fine for private family feedback — do not treat as production content.

04 · Step three — read this one fully

MongoDB with a replica set (required)

This is the step most likely to bite. The app's connection string — same shape as local dev — is mongodb://user:pass@127.0.0.1:27017/mishran?replicaSet=rs0&authSource=admin. A default standalone mongod will refuse that URI, and Payload's draft/publish system wants replica-set transactions anyway. So: install MongoDB 8.0, enable a single-node replica set named rs0, create the app user, and keep it bound to localhost.

Install MongoDB 8.0 (Ubuntu official repo — apt's default mongo package is old)
curl -fsSL https://www.mongodb.org/static/pgp/server-8.0.asc | \
  sudo gpg -o /usr/share/keyrings/mongodb-server-8.0.gpg --dearmor
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-8.0.gpg ] \
  https://repo.mongodb.org/apt/ubuntu noble/mongodb-org/8.0 multiverse" | \
  sudo tee /etc/apt/sources.list.d/mongodb-org-8.0.list
sudo apt update
sudo apt install -y mongodb-org
Enable replica set rs0 + bind to localhost only
sudo tee -a /etc/mongod.conf <<'EOF'
replication:
  replSetName: rs0
EOF
# mongod.conf should already have bindIp: 127.0.0.1 — verify:
grep bindIp /etc/mongod.conf

sudo systemctl enable --now mongod
sudo systemctl status mongod
Initiate the replica set (one-time)
mongosh --quiet --eval 'rs.initiate({_id: "rs0", members: [{_id: 0, host: "127.0.0.1:27017"}]})'
# wait ~10s, then confirm PRIMARY:
mongosh --quiet --eval 'rs.status().members[0].stateStr'
Create the app user
mongosh <<'EOF'
use admin
db.createUser({
  user: "mishran",
  pwd: "REPLACE_WITH_STRONG_DB_PASSWORD",
  roles: [
    { role: "readWrite", db: "mishran" },
    { role: "dbAdmin",   db: "mishran" }
  ]
})
EOF

Self-hosted by design. Local Mongo keeps with the project's infra rule: self-host first, stay cloud-swappable — if this grows up, an Atlas URI is a one-line MONGODB_URI swap later.

Never set bindIp: 0.0.0.0 or open port 27017 in ufw. Mongo stays private to the VPS.

05 · Step four

Get the code onto the VPS

The repo is a pnpm workspace monorepo (apps/*, packages/*). The web app lives at the repo root, but pnpm build runs a prebuild codegen that touches packages/ — so deploy the full checkout, never just the root files. The branch to deploy is main.

Option A — git clone (recommended)

The GitHub remote is https://github.com/rbyakod/malgudi-mithai-shop.git and appears private, so the VPS needs read access: simplest is a fine-grained PAT (repo → Read-only) used once in the clone URL, or an SSH deploy key.

Option B — rsync from the Mac

No Git auth needed. But beware: exclude media/ — Payload stores uploaded images there and --delete would wipe them on every re-sync.

Create a locked-down app user + directory
sudo useradd --system --create-home --shell /bin/bash mithai || true
sudo mkdir -p /opt/mithai-shop
sudo chown -R mithai:mithai /opt/mithai-shop
Option A: clone (run as the app user)
sudo -iu mithai
git clone https://<PAT>@github.com/rbyakod/malgudi-mithai-shop.git /opt/mithai-shop
# if already cloned later: cd /opt/mithai-shop && git pull origin main
# .claude/worktrees/... may show as an empty dir after clone — harmless, ignore it.
Option B: rsync from the Mac (run on the Mac, not the VPS)
cd /Users/ravibyakod/WORK/mithai-shop/mithai-shop
rsync -az --delete \
  --exclude node_modules --exclude .next --exclude .git \
  --exclude media --exclude .env \
  ./ root@2.24.221.70:/opt/mithai-shop/
# then on the VPS:
sudo chown -R mithai:mithai /opt/mithai-shop
Install dependencies
sudo -iu mithai
cd /opt/mithai-shop
pnpm install --frozen-lockfile
06 · Step five

Create the environment file

Names below match the repo's .env.example exactly. Two secrets to generate with openssl rand -hex 32; the seed scripts read this file via node --env-file=.env, so it must be named .env (not .env.local).

/opt/mithai-shop/.env
NODE_ENV=production
PORT=3000

# Mongo — single-node replica set rs0 (step 04), auth against admin DB
MONGODB_URI=mongodb://mishran:REPLACE_DB_PASSWORD@127.0.0.1:27017/mishran?replicaSet=rs0&authSource=admin

# openssl rand -hex 32 × 2
PAYLOAD_SECRET=REPLACE_WITH_SECRET_1
REVALIDATE_SECRET=REPLACE_WITH_SECRET_2

# Public URLs — set these BEFORE `pnpm build` (they're inlined into the client bundle)
NEXT_PUBLIC_SITE_URL=https://mishran.roohib.com
NEXT_PUBLIC_API_BASE_URL=https://mishran.roohib.com/api/mobile/v1
NEXT_PUBLIC_APP_NAME=Mishran
NEXT_PUBLIC_WHATSAPP_NUMBER=+91XXXXXXXXXX

# Lead-notification emails (leave empty for family test — leads are also visible in /admin)
LEADS_INBOX=
RESEND_API_KEY=

# Optional analytics — leave empty for private testing
NEXT_PUBLIC_GA4_ID=
NEXT_PUBLIC_META_PIXEL_ID=
Lock it down
sudo chown mithai:mithai /opt/mithai-shop/.env
sudo chmod 600 /opt/mithai-shop/.env

Order matters: set NEXT_PUBLIC_* values before the first build. If you change them later, you must pnpm build again — they are baked into the bundle at build time, not read at runtime.

07 · Step six

Build and run under systemd

pnpm build automatically runs the prebuild steps (import-map regen + TypeScript codegen for the workspace packages). First build takes several minutes and ~1–2 GB RAM — that's what the swap in step 03 is for.

Build
sudo -iu mithai
cd /opt/mithai-shop
pnpm build
/etc/systemd/system/mithai-shop.service
[Unit]
Description=Mishran Next.js + Payload app
After=network.target mongod.service
Requires=mongod.service

[Service]
Type=simple
User=mithai
Group=mithai
WorkingDirectory=/opt/mithai-shop
EnvironmentFile=/opt/mithai-shop/.env
ExecStart=/usr/bin/pnpm start
Restart=always
RestartSec=5
NoNewPrivileges=true
PrivateTmp=true

[Install]
WantedBy=multi-user.target
Enable + first check
sudo systemctl daemon-reload
sudo systemctl enable --now mithai-shop
sudo systemctl status mithai-shop
journalctl -u mithai-shop -f      # watch boot; Ctrl-C to exit

# from the VPS:
curl -I http://127.0.0.1:3000/en   # expect 200

Bare / redirects to /en automatically — that's the locale router (Next.js 16 proxy.ts), not a misconfiguration.

08 · Step seven

Nginx reverse proxy + HTTPS

client_max_body_size 25m matters — Payload admin image uploads go through this limit (the seed images live on disk already, but your own uploads via /admin need headroom).

/etc/nginx/sites-available/mishran.roohib.com
server {
    listen 80;
    listen [::]:80;
    server_name mishran.roohib.com;

    client_max_body_size 25m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_read_timeout 120s;
        proxy_send_timeout 120s;
    }
}
Enable + verify HTTP
sudo ln -s /etc/nginx/sites-available/mishran.roohib.com /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

curl -I http://mishran.roohib.com/en   # expect 200 — THEN do Certbot
Certbot (only after DNS + HTTP both work)
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d mishran.roohib.com
sudo certbot renew --dry-run        # auto-renew is a systemd timer — just confirm

curl -I https://mishran.roohib.com/en   # expect 200

Certbot rewrites the site to 443 + redirect automatically. Since NEXT_PUBLIC_SITE_URL was already https://… before the build, no rebuild is needed.

09 · Step eight

Seed the golden test data

The committed catalogs in scripts/seed-data/ reproduce the full 144-product test catalog. Seeds are idempotent — safe to re-run, they never duplicate.

Run the seeds (order matters)
sudo -iu mithai
cd /opt/mithai-shop

grep '^MONGODB_URI=' .env   # sanity-check: must be the VPS staging DB

pnpm seed            # base sample content (users, stories, packaging, …)
pnpm seed:catalog    # golden catalog — 76 mithai · 24 snacks · 20 qsr · 22 gifts
pnpm seed:branding   # brand-settings "Mishran" + sun logo + demo QSR image

sudo systemctl restart mithai-shop

What to expect from seed:catalog

  • Downloads ~200 product images from storefront CDNs + Wikimedia at runtime (nothing binary in Git) — takes several minutes.
  • Stores them as Payload media under /opt/mithai-shop/media/.
  • Expected result line: Seed complete: … Media: 200 ok, 0 skipped.

If media shows “skipped”

  • Usually HTTP 429 from Wikimedia rate-limiting. Just re-run pnpm seed:catalog — idempotency means only the gaps fill in.
  • Verify zero gaps: /api/qsr-menu-items — every doc's image should be set.
10 · Step nine

Create the first admin user

Payload's admin is at /admin. On first visit with an empty users collection it offers to create the first user — that account becomes the admin.

  1. Open https://mishran.roohib.com/admin.
  2. Create your user (use a real password — this is internet-facing).
  3. Look around: collections Mithai Products, Snack Products, QSR Menu Items, Gift Boxes should show the seeded counts.
  4. Globals → Brand Settings: confirm brandName Mishran and the sun logo.

Don't hand out admin accounts to family testers — they only need the storefront URL. The admin login page is public by nature; the strong password is the gate.

14 · When it breaks

Troubleshooting

SymptomCauseFix
App crash-loops; log shows MongoServerSelectionError or replica set connection timed out Mongo not running, or rs0 never initiated systemctl status mongod; then mongosh --eval 'rs.status()' — if uninitialized, run the rs.initiate() from step 04
Authentication failed (code 13) in app logs Wrong password in MONGODB_URI, or user created before rs.initiate() on a different auth setup Re-check .env; recreate user in the admin DB exactly as step 04; restart app
next build killed (exit 137 / "Killed") Out of RAM Add the swap from step 03, then rebuild
502 Bad Gateway App not listening on 3000 systemctl status mithai-shop + journalctl -u mithai-shop -n 100
Certbot fails / challenge error DNS not propagated or port 80 blocked dig +short mishran.roohib.com; sudo ufw status; retry after DNS resolves
Product images missing on cards Seed 429-skips (Wikimedia) or pages still ISR-cached Re-run pnpm seed:catalog; then sudo systemctl restart mithai-shop
Images 404 after a re-deploy via rsync media/ was wiped by --delete Restore media backup, or re-run seed:catalog (re-uploads); keep --exclude media in future syncs
Admin loads but media uploads fail (413) Nginx body limit Confirm client_max_body_size 25m; in the site file; sudo nginx -t && sudo systemctl reload nginx
15 · Safety net

Rollback

  1. Read the logs before changing anything: journalctl -u mithai-shop -n 200 --no-pager.
  2. Bad code deploy → cd /opt/mithai-shop && git log --oneline -5, then git checkout <last-good-sha>.
  3. Rebuild + restart: pnpm install --frozen-lockfile && pnpm build && sudo systemctl restart mithai-shop.
  4. Bad content only → fix in /admin, or re-seed: pnpm seed:catalog && pnpm seed:branding.
  5. Disaster → stop the site: sudo systemctl stop mithai-shop (Nginx will 502; DNS TTL 300 means the name frees up fast if you ever repoint it).

Git history on main has a tagged restore point — the merge commit d3809e3 "before codex ux/ui changes" — if the Codex UX/UI pass ever needs a full revert.
