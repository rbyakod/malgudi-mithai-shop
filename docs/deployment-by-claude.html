01 · Before touching anything

Inputs needed

Access

  • GoDaddy account that manages roohib.com (for step 02).
  • SSH user for 2.24.221.70 (root or a sudo user) + its password or key.

02 · Step one — in the browser, not the terminal

Create the subdomain at GoDaddy

A subdomain is just a DNS record: it tells the world "ask 2.24.221.70 for anything named mishran.roohib.com". This is done once, in GoDaddy's DNS manager, and costs nothing.

Click-by-click

  1. Go to godaddy.com and sign in (top-right).
  2. Open My Products (account menu, top-right) and scroll to the Domains section.
  3. Find roohib.com in the list. Do not click the domain name itself — instead click DNS → Manage Zones (or the ⋮ / Manage DNS option next to it). You want the DNS Management page whose header reads DNS Management | roohib.com.
  4. At the bottom of the records table click Add New Record. A blank row appears with dropdowns.
  5. Set Type to A (maps a name to an IPv4 address).
  6. Set Name to mishran — GoDaddy shows it as mishran.roohib.com once saved. Leave it as just mishran; typing the full domain creates a wrong nested name.
  7. Set Value to 2.24.221.70 (the VPS IP).
  8. Leave TTL at Default (or set 600 seconds — shorter = faster changes later).
  9. Click Save. The record appears in the table.

Pre-flight — confirm GoDaddy is actually answering for this domain

These checks matter only if roohib.com's nameservers were ever pointed elsewhere (e.g. Cloudflare). On the same DNS Management page, the Nameservers box should list GoDaddy servers like ns1.domaincontrol.com / ns2.domaincontrol.com.

If nameservers are NOT GoDaddy's — for example Cloudflare's *.ns.cloudflare.com — then GoDaddy's DNS page is being ignored, and you must instead add the same A record (mishran → 2.24.221.70, "DNS only", proxy off) in that provider's dashboard. The rest of this runbook is identical either way.

Verify propagation (from your Mac terminal)

Check the record is live — repeat every minute or two until it answers
dig +short mishran.roohib.com
# expect exactly: 2.24.221.70

# if empty at first, ask GoDaddy's nameservers directly (bypasses your Mac's cache):
dig +short mishran.roohib.com @ns1.domaincontrol.com

Propagation is usually under 5 minutes for a brand-new record. Certbot in step 08 will fail until dig answers 2.24.221.70 — so do this step first, then keep going with the server steps while it settles.

03 · Step two — on the VPS

Prepare Ubuntu

Connect

SSH in (Terminal on the Mac)
ssh root@2.24.221.70
# or: ssh <your-sudo-user>@2.24.221.70
# accept the fingerprint prompt the first time; type the password when asked

Update packages + install build tools

build-essential provides the C/C++ compiler toolchain — sharp (image processing) and argon2 (password hashing) compile native code during pnpm install and fail without it. Nginx is already installed here — we verify it instead of installing.

Update + base packages
sudo apt update && sudo apt upgrade -y     # refresh package lists, apply security updates
sudo apt install -y git curl ca-certificates build-essential ufw

# verify nginx (should already be active, serving your other subdomains):
sudo nginx -v
sudo systemctl status nginx --no-pager    # look for: Active: active (running)

Install Node 22 and pnpm

The app is developed on Node 22.x + pnpm 11.x; matching them avoids native-module surprises. NodeSource is the standard apt repository for current Node versions (Ubuntu's own nodejs package is too old). Corepack ships with Node and manages pnpm.

Node 22 via NodeSource, then pnpm via corepack
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -   # adds the NodeSource apt repo
sudo apt install -y nodejs
node -v     # expect v22.x.y

sudo corepack enable                       # exposes the pnpm shim
corepack prepare pnpm@latest --activate
pnpm -v     # expect 10.x or 11.x

Firewall — only if UFW isn't already set up

If you've been running public subdomains already, the firewall may be configured. Check first — enabling UFW carelessly can lock you out of SSH.

Check, then (only if inactive) configure
sudo ufw status
# "Status: active" with OpenSSH + Nginx Full listed → nothing to do.
# "Status: inactive" → run:
sudo ufw allow OpenSSH          # keep SSH allowed BEFORE enabling
sudo ufw allow 'Nginx Full'     # ports 80 + 443
sudo ufw --force enable
sudo ufw status

Optional but recommended on small VPSes: swap

Swap gives the server 2 GB of overflow memory on disk, which next build can spike into. Skip if the VPS has ≥ 4 GB RAM (check with free -h).

2 GB swap file (safe to skip on 4 GB+ machines)
free -h                                        # see total memory + existing swap
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile                       # only root can read it
sudo mkswap /swapfile && sudo swapon /swapfile
echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab   # persist across reboots
free -h                                        # Swap: 2.0Gi now shows
04 · Step three — read this one fully

MongoDB with a replica set (required)

This is the step most likely to bite. The app connects with mongodb://user:pass@127.0.0.1:27017/mishran?replicaSet=rs0&authSource=admin — same shape as local dev. A default standalone mongod refuses that URI, and Payload's draft/publish workflow wants replica-set transactions anyway. A "replica set" sounds like a cluster, but a single-node replica set is a one-line config change plus one command — that's all this is.

4.1 Install MongoDB 8.0 from MongoDB's own apt repo

Ubuntu's archive doesn't carry MongoDB at all (licensing), and old third-party mongodb packages are stale — always use MongoDB's official repo. The snippet below is for Ubuntu 24.04 (noble); check your release first.

Check Ubuntu release
lsb_release -cs
# "noble"  = Ubuntu 24.04  → use the repo line below as-is
# "jammy"  = Ubuntu 22.04  → replace every "noble" below with "jammy"
# "focal"  = Ubuntu 20.04  → replace with "focal"
Install (noble example)
# 1. import MongoDB's signing key
curl -fsSL https://www.mongodb.org/static/pgp/server-8.0.asc | \
  sudo gpg -o /usr/share/keyrings/mongodb-server-8.0.gpg --dearmor

# 2. add the repository (edit "noble" per your release check above)
echo "deb [ signed-by=/usr/share/keyrings/mongodb-server-8.0.gpg ] \
  https://repo.mongodb.org/apt/ubuntu noble/mongodb-org/8.0 multiverse" | \
  sudo tee /etc/apt/sources.list.d/mongodb-org-8.0.list

# 3. install + start
sudo apt update
sudo apt install -y mongodb-org
sudo systemctl enable --now mongod    # start now + on every boot
sudo systemctl status mongod --no-pager

4.2 Turn it into replica set rs0, bound to localhost

Append the replication block, confirm private binding, restart
sudo tee -a /etc/mongod.conf <<'EOF'
replication:
  replSetName: rs0
EOF

# mongod.conf normally ships with bindIp: 127.0.0.1 — verify it's still there:
grep bindIp /etc/mongod.conf            # expect: bindIp: 127.0.0.1

sudo systemctl restart mongod
sudo systemctl status mongod --no-pager

4.3 Initiate the replica set (one-time)

Config present isn't enough — the set must be kicked off once. This says "you are a one-member replica set named rs0".

rs.initiate() and confirm PRIMARY
mongosh --quiet --eval 'rs.initiate({_id: "rs0", members: [{_id: 0, host: "127.0.0.1:27017"}]})'
# expect: { ok: 1 }   (an "already initialized" message is also fine)

sleep 10    # elections take a few seconds
mongosh --quiet --eval 'rs.status().members[0].stateStr'
# expect: PRIMARY

4.4 Create the app's database user

The app never runs as the Mongo admin. This user can only touch the mishran database. Pick a strong password now — you'll paste it into .env in step 06. authSource=admin in the URI means "look this user up in the admin database", which is where we create it.

Create user "mishran" (replace the password)
mongosh <<'EOF'
use admin
db.createUser({
  user: "mishran",
  pwd: "REPLACE_WITH_STRONG_DB_PASSWORD",
  roles: [
    { role: "readWrite", db: "mishran" },
    { role: "dbAdmin",   db: "mishran" }
  ]
})
EOF
# expect: { ok: 1 }
Smoke-test the exact URI the app will use
mongosh 'mongodb://mishran:REPLACE_WITH_STRONG_DB_PASSWORD@127.0.0.1:27017/mishran?replicaSet=rs0&authSource=admin' --quiet --eval 'db.getName()'
# expect: mishran   ← if this prints, steps 06+ will connect first try

Self-hosted by design. Local Mongo follows the project's infra rule: self-host first, stay cloud-swappable — moving to Atlas later is a one-line MONGODB_URI change.

Never set bindIp: 0.0.0.0 or open port 27017 in any firewall. Mongo stays private to the VPS.

05 · Step four

Get the code onto the VPS

The repo is a pnpm workspace monorepo (apps/*, packages/*). The web app lives at the repo root, but pnpm build runs a prebuild codegen across packages/ — so deploy the full checkout of main, never a partial copy. Two ways to get it there; A is cleaner long-term.

5.1 Create a locked-down system user that will own the app

App user + directory
sudo useradd --system --create-home --shell /bin/bash mithai || true
sudo mkdir -p /opt/mithai-shop
sudo chown -R mithai:mithai /opt/mithai-shop

5.2 Option A — git clone (recommended)

The GitHub repo github.com/rbyakod/malgudi-mithai-shop is private, so the VPS needs read access via a fine-grained personal access token. Generate it once on your Mac — it takes two minutes:

  1. On GitHub, click your avatar (top-right) → Settings.
  2. Left sidebar, bottom: Developer settings.
  3. Personal access tokens → Fine-grained tokens → Generate new token.
  4. Token name: mishran-vps-read. Expiration: 90 days (you can regenerate).
  5. Resource owner: rbyakod. Repository access: "Only select repositories" → pick malgudi-mithai-shop.
  6. Permissions → Repository permissions → Contents: set to Read-only. Nothing else needs granting.
  7. Click Generate token and copy the value (starts with github_pat_). It's shown only once.
Clone as the app user (on the VPS)
sudo -iu mithai     # "become" the app user for this shell
git clone https://github_pat_XXXX@github.com/rbyakod/malgudi-mithai-shop.git /opt/mithai-shop

# note: .claude/worktrees/... may appear as an empty dir after clone — a git
# internal detail of this repo. Harmless; leave it.

Later updates are then just cd /opt/mithai-shop && git pull origin main — see step 13.

5.3 Option B — rsync from the Mac (no Git token needed)

Copies the working tree over SSH. The two critical excludes: media/ (Payload's uploaded images live there — --delete would erase them on re-syncs) and .env (never overwrite the server's secrets with your Mac's dev values).

Run on the Mac (not the VPS)

  --exclude node_modules --exclude .next --exclude .git \
  --exclude media --exclude .env \

# then on the VPS:
sudo chown -R mithai:mithai /opt/mithai-shop

sudo -iu mithai

06 · Step five

Create the environment file

Variable names below match the repo's .env.example exactly. The file must be named .env (the seed scripts read it via node --env-file=.env). Generate the two secrets first, then paste everything in one go.

6.1 Generate secrets

Two random hex strings (paste each into the file below)
openssl rand -hex 32     # → PAYLOAD_SECRET      (signs admin login sessions)
openssl rand -hex 32     # → REVALIDATE_SECRET  (protects the cache-refresh endpoint)

6.2 Write the file

Do this as the app user so ownership is right from the start: sudo -iu mithai, then nano /opt/mithai-shop/.env, paste, edit the three REPLACE values, save (Ctrl-O, Enter, Ctrl-X). Or use the heredoc below.

/opt/mithai-shop/.env — full contents
NODE_ENV=production
PORT=3000

# Mongo — single-node replica set rs0 (step 04), user auth against the admin DB
MONGODB_URI=mongodb://mishran:REPLACE_DB_PASSWORD@127.0.0.1:27017/mishran?replicaSet=rs0&authSource=admin

# the two openssl outputs
PAYLOAD_SECRET=REPLACE_WITH_SECRET_1
REVALIDATE_SECRET=REPLACE_WITH_SECRET_2

# public URLs — these are INLINED INTO THE BUNDLE AT BUILD TIME, so they must
# be correct BEFORE `pnpm build` (step 07)
NEXT_PUBLIC_SITE_URL=https://mishran.roohib.com
NEXT_PUBLIC_API_BASE_URL=https://mishran.roohib.com/api/mobile/v1
NEXT_PUBLIC_APP_NAME=Mishran
NEXT_PUBLIC_WHATSAPP_NUMBER=+91XXXXXXXXXX      # your WhatsApp business number, or leave as-is

# lead-notification emails — leave EMPTY for the family test; leads are also
# always visible inside /admin, so nothing is lost by leaving these blank
LEADS_INBOX=
RESEND_API_KEY=

# analytics — leave empty for private testing
NEXT_PUBLIC_GA4_ID=
NEXT_PUBLIC_META_PIXEL_ID=

6.3 Lock it down

Owner-only readable
sudo chown mithai:mithai /opt/mithai-shop/.env
sudo chmod 600 /opt/mithai-shop/.env      # rw for owner, nothing for anyone else

What each variable does

VariableWhy it exists
MONGODB_URIDatabase location + credentials. The replicaSet=rs0 and authSource=admin parameters are required by the setup in step 04.
PAYLOAD_SECRETSigns the Payload admin's login cookies. If it changes, everyone is logged out — nothing else breaks.
REVALIDATE_SECRETWhen you edit a product in /admin, Payload pings the site to refresh cached pages; this secret stops strangers doing the same.
NEXT_PUBLIC_SITE_URLCanonical URL used by sitemap, robots, and structured data. Must be the final https URL.
NEXT_PUBLIC_API_BASE_URLWhere the mobile apps' API advertises itself. Same host, /api/mobile/v1 path.
NEXT_PUBLIC_WHATSAPP_NUMBERPre-fills the contact/WhatsApp deep-links shown in the UI.
LEADS_INBOX / RESEND_API_KEYWhere enquiry-form submissions get emailed. Empty = no email, but every submission is still saved and viewable in /admin.

Order matters: set the NEXT_PUBLIC_* values before the first build. Changing them later requires pnpm build again — they're compiled into the client bundle, not read at runtime.

07 · Step six

Build and run under systemd

7.1 Build

pnpm build automatically runs the prebuild steps first (import-map regen + TypeScript codegen across the workspace packages) — no extra commands needed. Expect several minutes and noticeable RAM use; that's normal.

Production build
sudo -iu mithai
cd /opt/mithai-shop
pnpm build
# last lines should show the route table and "✓ Compiled successfully"

7.2 Create the systemd service

systemd is Ubuntu's process supervisor — it starts the app on boot and restarts it if it crashes. Run sudo nano /etc/systemd/system/mithai-shop.service, paste, save. Key lines explained below.

/etc/systemd/system/mithai-shop.service
[Unit]
Description=Mishran Next.js + Payload app
After=network.target mongod.service     # don't start before net + mongo
Requires=mongod.service                 # mongo down → app stops too (fails loudly)

[Service]
Type=simple
User=mithai                             # run as the locked-down app user
Group=mithai
WorkingDirectory=/opt/mithai-shop       # relative paths (media/, .next/) resolve here
EnvironmentFile=/opt/mithai-shop/.env   # the file from step 06
ExecStart=/usr/bin/pnpm start           # runs `next start` on PORT=3000
Restart=always                          # crash → auto-restart…
RestartSec=5                            # …after a 5s breather
NoNewPrivileges=true                    # hardening: no suid escalation
PrivateTmp=true                         # hardening: private /tmp

[Install]
WantedBy=multi-user.target              # "start on normal boot"

7.3 Start it and watch the boot

Enable + verify
sudo systemctl daemon-reload            # systemd re-reads service files
sudo systemctl enable --now mithai-shop # start now + on every boot
sudo systemctl status mithai-shop       # expect: active (running)

journalctl -u mithai-shop -f            # live log; wait for "Ready", then Ctrl-C

curl -I http://127.0.0.1:3000/en        # expect: HTTP/1.1 200 OK

Visiting bare / redirects to /en — that's the locale router working (Next.js 16 proxy.ts), not a bug.

08 · Step seven

Add the site to your existing Nginx, then HTTPS

Nginx is already running with other subdomains — this step only adds one more site file and touches nothing existing. The new config lives in its own file, exactly like your other subdomains, and every check gates a reload, so a mistake can never disturb the running sites.

8.1 Pre-flight

Confirm the name is free + see your layout convention
grep -r server_name /etc/nginx/sites-enabled/   # mishran.roohib.com must NOT appear anywhere
ls /etc/nginx/sites-enabled/ /etc/nginx/conf.d/ # see where existing sites live
sudo systemctl status nginx --no-pager           # active (running)
dig +short mishran.roohib.com                   # 2.24.221.70 — step 02 must be live

If your existing sites live in /etc/nginx/conf.d/*.conf rather than sites-available/, create the Mishran file there instead and skip the symlink in 8.3 — follow whichever layout the server already uses.

8.2 The site file

sudo nano /etc/nginx/sites-available/mishran.roohib.com and paste. What each directive does: server_name matches only this hostname (your other sites are unaffected); client_max_body_size 25m allows Payload admin image uploads (default 1m would reject them) — scoped to this site only; the proxy_set_header lines pass the visitor's real host/IP/scheme through; the Upgrade/Connection pair enables websockets if Next ever needs them.

/etc/nginx/sites-available/mishran.roohib.com
server {
    listen 80;
    listen [::]:80;
    server_name mishran.roohib.com;

    client_max_body_size 25m;

    location / {
        proxy_pass http://127.0.0.1:3000;      # → the systemd app
        proxy_http_version 1.1;

        proxy_set_header Host $host;           # e.g. mishran.roohib.com
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;   # http now, https after certbot

        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";

        proxy_read_timeout 120s;               # long admin operations
        proxy_send_timeout 120s;
    }
}

8.3 Enable + verify over HTTP

Test, then reload — reload (not restart) keeps other sites serving
sudo ln -s /etc/nginx/sites-available/mishran.roohib.com /etc/nginx/sites-enabled/

sudo nginx -t                # syntax check. If this FAILS: fix the file; nothing has been applied yet.
sudo systemctl reload nginx  # only runs if -t passed (we chain with && in practice)

curl -I http://mishran.roohib.com/en    # expect 200 — THEN continue to Certbot

8.4 HTTPS via Certbot

Certbot proves to Let's Encrypt that you control the domain (via the now-working HTTP site), fetches a free certificate, rewrites only the Mishran site file to listen on 443, and adds an auto-renewal timer. It will ask a few questions — answers below.

Install + run
sudo apt install -y certbot python3-certbot-nginx    # no-op if already present
sudo certbot --nginx -d mishran.roohib.com
  1. Email address — enter your email (used only for expiry notices; auto-renew makes expiries unlikely).
  2. Terms of Service — type A and Enter to agree.
  3. Share email with EFF? — N is fine.
  4. If it offers redirect choices ("No redirect" vs "Redirect"), choose Redirect — all traffic becomes HTTPS automatically.
  5. Expect Certificate deployed successfully (or "Deploying a certificate… Successfully deployed").
Confirm renewal + final check
sudo certbot renew --dry-run             # renews ALL certs incl. other subdomains — should all pass
curl -I https://mishran.roohib.com/en    # expect 200; http:// should 301-redirect to https://

Certbot edited only the mishran site file. Other subdomains' configs are untouched; if they use certificates from a different issuer that's fine — a hostname can only have one cert and this name is new. Because NEXT_PUBLIC_SITE_URL was already https://… before the build, no rebuild is needed.

9.3 What seed:catalog is doing during those minutes

Downloads images at runtime

  • Image bytes aren't in Git — the seed fetches each product's image from the original CDN / Wikimedia URLs and uploads them as Payload media into /opt/mithai-shop/media/.
  • That's why the VPS needs outbound HTTPS and why it takes minutes.

If the log shows “Media: N skipped”

  • Almost always HTTP 429 — Wikimedia rate-limiting a burst.
  • Fix: just re-run pnpm seed:catalog. Idempotency means only the gaps fill in.
  • Goal state: 0 skipped.

15 · Safety net

Rollback

  1. Read before changing: journalctl -u mithai-shop -n 200 --no-pager.
  2. Bad code deploy → cd /opt/mithai-shop && git log --oneline -5, then git checkout <last-good-sha>.
  3. Rebuild + restart: pnpm install --frozen-lockfile && pnpm build && sudo systemctl restart mithai-shop.
  4. Bad content only → fix in /admin, or re-seed: pnpm seed:catalog && pnpm seed:branding.
  5. Take the site offline: sudo systemctl stop mithai-shop (URL will 502; DNS TTL 300 frees the name quickly if ever repointed).
  6. Remove the site from Nginx entirely: delete the symlink + file, sudo nginx -t && sudo systemctl reload nginx — other subdomains unaffected.

Git history on main holds a tagged restore point — merge commit d3809e3 "before codex ux/ui changes" — if the Codex UX/UI pass ever needs a full revert.
