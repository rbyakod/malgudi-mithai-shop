The Mishran admin deserves better clothes

A full walkthrough of the Payload admin at mishran.pranavb.com/admin: what makes it feel dull and pale (a two-token CSS gap — fixable in an afternoon), six live defects, the information-architecture cleanup, and a three-tier roadmap that turns the console into the shop’s cockpit.

2026-08-18 · 16 screens captured (desktop 1440px + mobile 390px) · DOM-fact + computed-style verified · read-only with owner-provided credentials

00 · Summary & scorecard

The admin has good bones and a broken skin. The cream Mishran theme does apply to the page canvas — but a token gap leaves every input, border, and table header on Payload’s default gray. Warm cream wearing gray accessories is exactly the “dull and pale” impression. Beneath that: a widget that 405s, eleven hydration errors, one blank admin screen, a stray field leaking into every form, 36 slug-speak sidebar links, and raw API names (“Totals > Total In Paise”) on money fields.

Highest-leverage single fix

Close the theme token gap — --theme-elevation-0/150 plus the --color-base-* layer — in custom.scss. One CSS block recolors every control, border, and table header across the entire admin. See §02.

A weekend of P0 fixes moves this to 7+. The foundation — data model, custom widgets, theme system — is worth dressing properly.

02 · The “dull & pale” root cause

Working: body[data-admin-theme="mishran-admin"] applies — live-computed background rgb(247,239,224) (the cream), text rgb(42,26,14), and --theme-elevation-50 correctly overridden to #f7efe0.

Broken: Payload’s component library doesn’t read “background” for most chrome — it reads an elevation ladder, and custom.scss overrides only --theme-elevation-50…900. It never touches:

  • --theme-elevation-0 — input and card fills
  • --theme-elevation-150 — the border color (--theme-border-color aliases it)
  • the entire --color-base-* layer the ladder is built from
TokenOn :rootOn themed body
--theme-elevation-50#f5f5f5#f7efe0 overridden
--theme-elevation-150#ddd#ddd missed
text-input border (computed)—rgb(221,221,221) = #ddd

So: cream canvas, white inputs with default gray hairline borders, gray 13px table headers, gray rules. That dissonance is the pale.

The fix — one block in custom.scss

body[data-admin-theme] {
  /* close the ladder: the two missing rungs + the base layer it is built from */
  --theme-elevation-0:   #fffdf8; /* inputs, sticky headers on cream */
  --theme-elevation-150: #e6d9bd; /* ALL borders — the #ddd culprit */
  --color-base-0:   #fffdf8;
  --color-base-100: #f7efe0;
  --color-base-150: #e6d9bd;
  /* …mirror the warm ramp already used for elevation-50…900 */
}

Verify after applying

Keep the ladder monotonic with the existing 50–900 ramp; re-check computed borders in DevTools. The alternate themes (mishran-midnight, mishran-monsoon) need the same two rungs + base layer.

03 · Live defects P0

D1
Recent-leads widget 405s

“Couldn’t load leads. Error: 405 Method Not Allowed on /leads?limit=5&sort=-createdAt&depth=0” — the REST base is /api/…; the widget calls the page route.

Point the fetch at /api/leads — or use the Local API since the widget renders server-side.

D2
11 hydration errors, every page

Minified React error #418 (text/HTML mismatch) ×11 in one session.

Usually a date/relative-time rendered differently server vs client — audit the four dashboard widgets first.

D3
Pincodes admin is blank

The correct camelCase route /admin/collections/serviceablePincodes renders an empty <main> — no list, no “Create New”.

Debug the view config — likely a broken admin block or access function on that collection.

D4
“Admin theme” leaks into every form

The label appears at the end of all five dumped forms (order edit, theme/brand settings, home hero). The settingsMenu component renders as a pseudo-field.

Relocate the switcher out of settingsMenu — e.g. afterNavLinks in the sidebar, or the account view.

D5
Title says “Dashboard - Payload”

document.title on every screen — no suffix configured.

admin.meta.titleSuffix: " — Mishran" in payload.config.ts.

D6
Theme switcher undiscoverable

The only “theme” affordance found by traversal is the Theme Settings global link.

Ships with D4’s relocation into visible chrome.

04 · Information architecture — 36 links, six groups, slug-speak

The sidebar exposes 36 destinations across 01 Brand · 02 Products · 03 Catalog Ops · 04 Storefront · 05 Settings plus an unnumbered commerce cluster. Three problems:

  1. Slug-derived labels. “Qsr Menu Items”, “Otp Requests”, “Packagings” — the collection slug with a space and a capital. Payload’s labels: {singular, plural} exists for exactly this.
  2. System tables sit beside merchandising. Cart Drafts, Otp Requests, Security Events, Snapshots, Devices are operational exhaust an owner shouldn’t scroll past daily — hide via admin.hidden (or a collapsed “System” group) without removing the data.
  3. No task entry points. The nav answers “which table?” — never “fulfill today’s orders”, “moderate reviews”, “reconcile COD cash”.

05 · Forms & workflows — raw fields, no shape

Product edit: one flat column of ~20 labels — Name, Slug, Family, Ingredients, Allergens, Shelf Life, Storage, Freshness Status, Dietary Tags, Box Compatibility, Packaging Compatibility, Lead Time, three upload fields all labeled just “Image”, Story, Karigar, Display Price, Featured, Weight. No tabs, no sections, no descriptions.

Order edit: 26 flat labels including Customer Id, Price In Paise, Items Total In Paise, Delivery Fee In Paise, Taxes In Paise, Razorpay Order Id, Cart Snapshot Id — and the stray “Admin theme” (D4). Tabs: none.

Globals: same story — Home Hero is an autoplay-interval field plus five identical Product + Caption Override pairs: no thumbnails, no reorder, no preview.

Fixes, in impact order

  1. Tabs / named groups — product (Content · Sourcing · Logistics · Media) and order (Items · Totals · Payment · Fulfillment).
  2. Human labels + admin.description everywhere: “Price (₹)” not Price In Paise.
  3. Rupee-display components for money fields — store paise, display ₹.
  4. Named uploads: “Hero image”, “Gallery image 2”, “Packaging photo” — not 3× “Image”.
  5. Relationship fields with searchable select and a human secondary display (customer name, not raw id).

06 · Lists & tables — data without affordances

  • Orders: ID · Customer Id · Status · Payment Method · Totals > Total In Paise · Created At — an id and a paise integer where a name and ₹ belong.
  • Mithai: Name · Slug · Family · Ingredients — no thumbnail, no price for a visual catalog of 91 sweets.
  • Media: a text table of File Name · Alt · Updated At · Created At — the brand’s food photography has no grid view.
  • Customers / Coupons: the same gray grid (Phone · Name · Locale; Code · Discount Type · Value · Active · Used Count).

Fixes: curated defaultColumns per collection (thumbnail + display price + freshness pill for mithai; customer name + ₹ total + status pill for orders), a media grid view, status rendered as colored pills, and saved filter presets — “New orders today”, “Pending COD”, “Low freshness stock”.

07 · Dashboard — four good widgets drowning in 92 cards

The custom grid (Recent leads · Mithai freshness · Pending stories · Catalog counts) is the right instinct — freshness (Made daily 11 · Made to order 8 · Batch frozen 1) and catalog counts (Mithai 91 · QSR 33 · Snacks 39 · Merch 1 · Gift Boxes 23) are genuinely useful. But below them sit 92 default collection cards, the leads widget is a 405 (D1), and there are no orders, no revenue, no imagery.

An owner’s dashboard should answer the day in one glance

Orders to fulfill · revenue today/this week · COD cash to reconcile · reviews awaiting moderation · freshness alerts. All five derive from data that already exists.

08 · Login & brand moments

The login screen reads muted and internal: small wordmark, technical “Mishran editor console” tone, no boutique warmth. High-impact moves: a warm ivory card on a deeper maroon field, the serif display lockup with tagline hierarchy, a gold rule, tactile focus and hover states. The custom wordmark/crest graphics already exist — they’re under-dressed, not missing.

Empty states (“No pending drafts. Start a new story →”) already have the right friendly voice — keep it everywhere.

09 · Mobile (390px)

The shell survives: nav collapses to a drawer, widgets stack. But 92 cards make the dashboard an endless scroll, and no owner task (check today’s orders, reconcile COD) is reachable in under a minute. Post-P1 (ops dashboard + hidden system cards), consider a deliberate “owner mobile” surface: today’s orders + COD tally + review queue.

10 · Accessibility & trust

  • Hydration errors (D2) are robustness bugs with accessibility echoes — mismatched text nodes.
  • Gray-on-cream table headers at 13px sit near the contrast edge; when the warm token fix lands (§02), re-check text tokens (--theme-elevation-600+) for ≥ 4.5:1.
  • Focus states exist but are default — brand the ring in gold.

14 · Post-deploy follow-ups — 2026-08-19

Follow-ups from live use after the overhaul shipped (commits 4abf17b + the thumbnail fix).

Sidebar visibility

Group titles bolder and larger — px-based, because the admin root computes rem ~25% smaller than the storefront. The persistent rail (≥1441px viewports) now wears the Mishran maroon with cream/gold accents.

Active-route marker

The current nav entry is a <div>, not an <a> — Payload renders no class or aria hook for it. Styled via a div.nav__link tag selector in unlayered custom.scss (gold marker).

Cinematic hero autoplay

A resting cursor no longer pauses the rotation — hover-pause now applies to the framed hero only. Keyboard focus still pauses; reduced-motion is honored.

VPS image cache

nginx disk-caches /_next/image + media files (30-day TTL, ~8.6× faster repeat loads); deploys warm the cache automatically (scripts/warm-image-cache.sh). Ended the broken-image burst on product pages after each deploy — see docs/deployment.md §8.

D7 — list thumbnails 400 on bare media IDs

D7 Fixed List views query at depth=0 (Payload’s design for list performance), so images[0].image arrives as a bare media ID string — which the product cells passed straight to next/image: /_next/image?url=<24-hex>&w=96 → instant 400 for every row (514 logged on prod nginx in one afternoon). Fix, contained in the cell layer: pickImage classifies strings (URL-looking pass through, bare IDs render <MediaThumb>), and a module-level resolver batches every pending ID on the page into one GET /api/media?where[id][in]=…&depth=0 call (40 ms coalescing, 50-ID batches, useSyncExternalStore). Rows show the styled fallback until the batch lands, then swap to a real 48px thumbnail; failed lookups keep the fallback. 4 new unit tests — payload-admin suite 92/92.

Verification

Local probe with a real image relation: row rendered at depth=0 resolved to /_next/image?url=%2Fapi%2Fmedia%2Ffile%2F…&w=96, zero bare-ID srcs · 92/92 admin tests · pnpm build green.
