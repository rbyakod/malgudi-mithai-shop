For new Mishran admins

Run the Mishran admin from first login to daily operations.

This guide explains what each admin feature does, when to use it, how to update it, and what good sample data looks like. Use it for onboarding, daily checklists, and operational handoffs.

Primary goal

OperateOrders, payments, shipments, leads, catalog, and storefront content from one place.

Best first page

DashboardThe Mishran command center shows fulfillment, COD risk, revenue, reviews, leads, freshness, and catalog health.

Admin pattern

List, open, editUse collection lists to search and filter. Open a row to update. Save or publish when done.

Data rule

Be exactProduct names, slugs, order states, money in paise, and delivery areas affect customer-facing behavior.

Daily Rhythm

A new admin should start here every day. The dashboard is designed to surface the most important work before editing individual records.

Morning opening check

  • Open Admin home after login.
  • Review To fulfill and move paid orders into the next operational stage.
  • Review COD cash to collect so staff know which deliveries need payment collection.
  • Check Mithai freshness for products marked made daily, made to order, or batch frozen.
  • Open Reviews to moderate and reject unsafe or irrelevant reviews before approving good ones.

End of day close

  • Confirm delivered orders have shipment history updated.
  • Make sure COD delivered orders have payment status updated when cash is collected.
  • Review recent leads and mark contacted, qualified, won, or lost.
  • Check drafts and pending stories so promotional content does not sit unfinished.
  • Disable expired coupons or confirm the active date range is correct.

Golden rule

Never change order totals, payment records, or webhook data unless you are correcting a confirmed operational error. These fields are tied to customer receipts and payment reconciliation.

Dashboard

The dashboard is the admin home page. The top command center gives the business pulse, then the widgets guide the next action.

Mishran Command Center

The top dashboard area is a premium overview for operations. It tells the admin what matters today and gives a direct Review orders button.

  • Use when: starting a shift, checking what needs attention, or briefing a store manager.
  • How to use: click Review orders to open recent orders sorted newest first.
  • Good habit: begin every admin session from Admin home, then go into the specific collection.

Ops Pulse Tiles

These tiles summarize core operational risk and revenue.

  • To fulfill: confirmed, packed, dispatched, or out for delivery orders.
  • COD cash to collect: COD orders with pending payment status.
  • Paid today and paid this week: paid order totals.
  • Reviews to moderate: pending customer reviews.

Recent Leads

Shows new wedding, corporate, wholesale, gift, merch, or general enquiries.

  • Use quick status updates to mark contacted, qualified, won, or lost.
  • Use the phone or WhatsApp link when a phone number is present.
  • Keep the lead status clean so future follow-up is easy.

Freshness and Catalog Health

The freshness board groups published mithai by fulfillment promise. Catalog counts show how much content exists in each product collection.

  • Use made daily for fresh products with short shelf life.
  • Use made to order for products that need lead time.
  • Use batch frozen only when the product promise allows it.

Shared Admin Actions

Most admin pages follow the same pattern. Learn these once, then use them everywhere.

Find records

Open a collection from the sidebar, search by name or identifier, sort columns, then open the row.

Create records

Use the plus button or Create new button. Fill required fields first. Add media, relationships, and sidebar fields before publishing.

Save, publish, cancel

Use Save for normal updates. Use Publish on drafted content. Use Cancel to leave edit screens without saving unwanted changes.

Product drafts and autosave

Product collections (Mithai, Snacks, QSR, Merch, Gift Boxes) autosave your work as a draft every few seconds while you edit. Nothing goes live until you press Publish — customers and the mobile apps only ever see published products, so you can rework copy or photos safely.

  • Leaving an edit mid-work is safe: the draft keeps your progress.
  • Publish when the product is ready for the storefront.

Use slugs carefully

Slugs power stable URLs and app references. Use lowercase words with hyphens, for example kaju-katli.

Use media intentionally

Upload clean product photos. For product galleries, the first image is used as the hero image on cards and detail pages.

Check localized fields

Some copy fields are localized. Make sure the main English copy is complete first, then add language variants when available.

Orders

Orders are the operational source of truth for customer purchase, payment status, delivery slot, items, and totals.

How to use Orders

  • Open 06 Commerce, then Orders.
  • Sort by created date to see the newest orders first.
  • Filter by status when working through fulfillment.
  • Open an order and review customer, order status, payment status, payment method, source, coupon code, and delivery slot.
  • Use the Items tab to verify products, quantity, pack label, unit, and unit price.
  • Use Payment and delivery to confirm Razorpay order ID, delivery address, and cart snapshot reference.

    "date": "2026-10-18",
    "window": "10:00 AM to 12:00 PM"

Ops Consoles

The staff consoles are purpose-built screens for daily operations, separate from the record-editing admin. Sign in at /admin first — every console asks for staff auth and shows a sign-in hint if the session is missing or expired.

Orders console

Open /staff/orders-board. Two views: the board (orders grouped by fulfillment stage) and All orders (one table with filters, date bounds, and phone or order-id search, refreshing every 20 seconds).

  • Move orders through legal stages only — the Move to list shows the allowed next steps.
  • Cash collected marks a COD delivery paid after the envelope is in hand.

Packing slip

Click Slip on any order row (or Packing slip on a board card) to open a print-ready slip: order short id, customer and delivery address, itemized lines with quantities and money in rupees, totals, and the payment method badge.

  • Use Print to send it to the kitchen or courier.
  • Nothing is edited from the slip — it is read-only.

Export orders to CSV

In All orders, set the filters you want (dates, status, payment, source), then click Export CSV. The file follows the current filters exactly and downloads as mishran-orders-<from>-<to>.csv.

  • Use it for accountant handoffs, reconciliation, and sales reviews.
  • Exports are capped at 5000 rows — narrow the dates for larger ranges.

Refund a prepaid order

Paid online orders show a Refund button. Confirming sends a real refund through the payment gateway — this cannot be undone.

  • Default refunds the full un-refunded remainder; partial amounts go through the API with an explicit amount.
  • COD orders cannot be refunded here — cash settles offline at the door.
  • Every refund is recorded on the payment record with who, when, why, and the provider refund id.

Pincode import

Open /staff/pincodes to manage delivery coverage in bulk. Paste CSV text or choose a .csv file, then Validate only for a dry run or Import to write.

  • Columns: pincode, city, state, tier (fresh or shelf), slaDays, active. Common aliases like pin or days are accepted.
  • Existing pincodes are updated, new ones created — upsert by pincode.
  • Rows with problems are listed by line number and never written; the limit is 2000 rows per import.

Payment reconciliation

Open /staff/payment-reconciliation to compare provider payments against local records before closing the books.

Payments

Payments track provider status and reconciliation. Payment amounts are stored in paise, so 10000 means INR 100.

What it is

A payment row connects an order to a payment provider such as Razorpay, Cashfree, or PhonePe. It stores provider IDs, payment status, amount, method, and raw webhook events.

How to use

  • Use Payments to investigate failed, captured, refunded, or partially refunded transactions.
  • Compare provider order ID and provider payment ID with the payment dashboard.
  • Do not edit raw webhook events by hand.

Refund records

Ops refunds from the orders console write back here automatically: the accumulated Refunded amount plus one audit row per refund — provider refund id, amount, reason, who approved it, and when.

  • Read refunds for reconciliation; never create them by hand.
  • A payment is fully refunded when Refunded equals the Amount.

Sample payment

{
  "order": "Order 1042",
  "provider": "razorpay",
  "providerOrderId": "order_RZP_1042",
  "providerPaymentId": "pay_RZP_7788",
  "status": "captured",
  "amountInPaise": 116000,
  "currency": "INR",
  "method": "upi"
}

Shipments

Shipments track fulfillment stage, delivery ETA, external tracking IDs, and the stage history that staff can audit later.

How to use

  • Create one shipment per order.
  • Keep current stage aligned with the order status.
  • Add a history row whenever a shipment moves stage.
  • Add ETA and provider tracking ID when available.

Sample shipment

{
  "order": "Order 1042",
  "currentStage": "out_for_delivery",
  "eta": "2026-10-18T12:00:00",
  "providerShipmentId": "SHIP-7788",
  "providerTrackingId": "TRK-7788",
  "history": [
    {
      "stage": "packed",
      "at": "2026-10-18T08:45:00",
      "note": "Packed at Indiranagar store",
      "actor": "Store staff"
    }
  ]
}

Coupons

Coupons define campaign rules. Enforcement happens in commerce services, while admins manage the code, discount rule, active dates, limits, and active flag.

How to create a coupon

  • Open 06 Commerce, then Coupons.
  • Use uppercase coupon codes, for example DIWALI10.
  • Choose percent or flat discount.
  • For flat discounts, enter paise. INR 100 is 10000.
  • Add active from and active to dates.
  • Set usage limits when the campaign should stop automatically.

Sample coupon

{
  "code": "DIWALI10",
  "discountType": "percent",
  "value": 10,
  "minSubtotalInPaise": 100000,
  "maxDiscountInPaise": 25000,
  "activeFrom": "2026-10-01",
  "activeTo": "2026-10-31",
  "usageLimitTotal": 500,
  "usageLimitPerCustomer": 1,
  "active": true
}

Reviews

Reviews are created by the mobile review API and moderated in admin. They are not manually created from the collection page.

Moderation workflow

  • Open Reviews from the dashboard tile or Storefront group.
  • Filter status to pending.
  • Open each review and inspect product, customer, rating, body, order, and verified purchase.
  • Set status to approved if useful and safe.
  • Set status to rejected if spam, abusive, unrelated, or unsafe.

Sample review

{
  "product": "Kaju Katli",
  "customer": "Asha Rao",
  "authorName": "Asha",
  "rating": 5,
  "body": "Fresh, delicate, and perfect for gifting.",
  "order": "Order 1042",
  "verifiedPurchase": true,
  "status": "pending"
}

Leads

Leads capture high intent enquiries such as wedding, corporate, wholesale, gift builder, merch, and general requests.

How to use Leads

  • Open the dashboard Recent Leads widget or the Leads collection.
  • Read contact name, email, phone, company, GSTIN, source, and payload.
  • Use payload for event date, quantity, budget, city, selected products, and message.
  • Update status after each follow-up: new, contacted, qualified, won, or lost.
  • Use convertedFromDraft when a cart or gift builder draft becomes a real lead.

Mithai

Mithai is the core product collection. It powers product cards, product detail pages, freshness messaging, sourcing, cross-sells, and featured rails.

Create a mithai product

  • Open 02 Products, then Mithai.
  • Fill Details: name, slug, family, freshness status, display price, weight, featured.
  • Fill Content: ingredients, allergens, dietary tags, and story.
  • Add Media. The first image becomes the hero image.
  • Add Sourcing relationships: karigar, box compatibility, packaging compatibility.
  • Add Logistics: shelf life, storage, and lead time.
  • Save draft if incomplete. Publish when ready for the storefront.

Sample mithai

{
  "name": "Kaju Katli",
  "slug": "kaju-katli",
  "family": "classic",
  "freshnessStatus": "made-daily",
  "displayPrice": "INR 580",
  "weight": "500 g",
  "featured": true,
  "ingredients": "Cashew, sugar, ghee, cardamom.",
  "allergens": ["tree nuts", "dairy"],
  "dietaryTags": ["vegetarian"],
  "shelfLife": "7 days",
  "storage": "Keep in a cool, dry place.",
  "leadTime": "24 hours"
}

Gift Boxes

Gift boxes define gifting products, packaging layouts, compatible mithai, add-ons, and curated assortments.

How to use Gift Boxes

  • Create one gift box per sellable hamper or packaging concept.
  • Choose size: 4-piece, 8-piece, 16-piece, or custom.
  • Add compartment layout so operations know the packing plan.
  • Link compatible mithai and packaging.
  • Add optional add-ons such as carry bag, sleeve, ribbon, or card.
  • Add curated assortments for common gift choices.

Sample gift box

  "addOns": [
    { "label": "Gold sleeve", "type": "sleeve" },

QSR Menu

QSR menu items are quick service items such as chaat, chole bhature, kulcha, thaali, Chinese, and South Indian dishes.

How to use QSR Menu

  • Create one row per menu item.
  • Choose the correct category.
  • Add description, image, veg flag, and spice level.
  • Add store slugs in availableAtStores so staff know where the item is available.

Snacks And Merch

Snack products and merch support non-mithai catalog lines. Use them for namkeen, cookies, dry fruit products, and branded items.

Snack product use

  • Create rows for namkeen, cookie, and dry fruit products.
  • Add weight, description, images, retailers, and MSRP.
  • Use clean product naming so catalog counts and storefront cards stay readable.

Merch product use

  • Create rows for branded bags, tins, gifting accessories, or limited merchandise.
  • Add images and customer-facing copy before publishing.
  • Use Merch for real sellable branded objects, not packaging records.

Media

Media stores images used by products, stories, hero slides, karigars, farms, packaging, and brand settings.

What to upload

Use sharp, bright, premium product photos. Avoid screenshots, low light images, overly cropped images, and files with unclear names.

Good naming

Use descriptive names such as kaju-katli-500g-hero.jpg or diwali-heritage-box-open.jpg.

Operational note

For product image arrays, drag the strongest image to the first row because it becomes the hero image.

Stories

Stories support Mishran brand storytelling across farm, milk, karigar, packaging, festival, regional, recipe, and journal pillars.

Create a story

  • Add title and slug.
  • Choose the correct pillar.
  • Write body and excerpt.
  • Add hero image.
  • Link related products and verticals.
  • Add publishedAt and publish when ready.

Sample story

{
  "title": "The Karigar Behind Our Kaju Katli",
  "slug": "karigar-behind-kaju-katli",
  "pillar": "karigar",
  "excerpt": "Meet the maker behind a Mishran classic.",
  "relatedProducts": ["Kaju Katli"],
  "relatedVerticals": ["mithai"],
  "publishedAt": "2026-09-01"
}

Storefront Settings

Storefront globals control brand presentation, navigation, home hero, theme direction, analytics, and store locations.

Brand Settings

Controls logo, brand name, tagline, positioning, hero copy, and default theme.

{
  "brandName": "Mishran",
  "tagline": "Premium mithai, made with craft.",
  "defaultTheme": "mishran-default"
}

Home Hero

Controls the home page hero carousel. Add up to 12 product slides and drag to reorder. First row appears first. Every slide row shows a live preview of the picked product — photo, name, and vertical — so you can curate without guessing, and the Preview button opens the live storefront home in a new tab.

{
  "autoplayMs": 5000,
  "slides": [
    {
      "product": "Diwali Heritage Box",
      "captionOverride": "Festive gifting, ready to send"
    }
  ]
}

Navigation Settings

Controls primary and utility navigation labels and links. Keep labels short and customer friendly.

Theme Settings

Controls storefront theme tokens, layout mode, hero style, product image motion, theme switcher visibility, and catalog page size.

Analytics Settings

Stores GA4 ID, Meta Pixel ID, Hotjar ID, and WhatsApp number. Use exact IDs from each platform.

Store Settings

Stores physical locations, city, address, hours, delivery radius, latitude, and longitude.

  "deliveryRadiusKm": 8,

Customers And Delivery

Customer and delivery collections help admins support orders, addresses, delivery coverage, app devices, and customer service.

Customers

Stores phone, Apple sign-in ID, auth provider, name, email, locale, default addresses, last IP, and last seen time. Use this to identify the customer behind an order.

Addresses

Stores customer address, city, state, pincode, coordinates, address tag, and default flag.

Delivery Areas

Serviceable pincodes decide whether Mishran can deliver fresh or shelf stable products to a location.

Devices and security

Devices, OTP requests, revoked tokens, idempotency keys, and security events are mostly system records. Use them for support and security investigation, not routine editing.

  "tier": "fresh",
  "city": "Bengaluru",
  "state": "Karnataka",
  "slaDays": 0,
  "active": true
}

New Admin Checklist

Use this checklist in the first training session. The admin is ready when they can complete these without help.

Priority Task Admin should demonstrate
P0 Open Admin home and explain every dashboard tile. Understands to fulfill, COD cash, revenue, reviews, leads, freshness, and catalog counts.
P0 Find an order and update its status correctly. Can move an order through confirmed, packed, dispatched, out for delivery, and delivered.
P0 Moderate pending reviews. Approves useful reviews and rejects unsafe or irrelevant reviews.
P1 Create or update a mithai product. Uses slug, freshness, image order, content, sourcing, and logistics correctly.
P1 Follow up and update a lead. Reads payload, contacts customer, changes status, and keeps notes clean.
P2 Create a coupon. Uses percent or paise values correctly and sets date and usage limits.
P2 Update home hero and brand settings. Can reorder slides, choose products, and keep brand copy polished.
P3 Explain system records. Knows that OTP, devices, security events, revoked tokens, and idempotency records are for investigation, not daily editing.
