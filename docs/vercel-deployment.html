Vercel Deployment Guide

A step-by-step recipe to take the Mishran repo from a fresh clone to a live production deploy backed by MongoDB Atlas, with Payload CMS reachable at /admin.

Audience: developer with Vercel + MongoDB Atlas accounts Stack: Next.js 16 · Payload 3.87 · MongoDB · Vercel bom1

0. Prerequisites

  • Node 22.x — matches the Vercel build image. Verify with node -v.
  • A Vercel account with the project repo connected (or permission to connect).
  • A MongoDB Atlas account (free M0 tier is fine to start).
  • A Resend account + API key with a verified sending domain.
  • The canonical production domain (e.g. mishran.shop) with DNS access.

1. MongoDB Atlas setup

1.1 Create an M0 (free) cluster

  • Region: AWS Mumbai (ap-south-1) to match Vercel bom1. Cross-region latency between Atlas and the function is the single biggest page-speed lever.
  • Name it mishran-prod (or similar).
  • M0 is shared-tier — fine until traffic forces upgrade to M10+ for VPC peering.

1.2 Create a database user

  1. Database Access → Add new user.
  2. Username: mishran-app. Password: 32-char random (openssl rand -base64 24).
  3. Role: readWriteAnyDatabase on M0. On M10+ scope to mishran database only.
  4. Save the password — it goes into MONGODB_URI in Step 3.

1.3 Network access — IP allowlist

Important: Vercel's egress IPs are dynamic. The M0 tier does not support VPC peering or static egress IPs from Vercel. The reliable path is to allow 0.0.0.0/0 (any IP).
  • Security trade-off: 0.0.0.0/0 exposes the cluster to brute-force attempts from anywhere. The DB user password is the only barrier — make it strong.
  • Atlas's built-in auth throttling + a strong password make brute-force impractical.
  • As soon as you upgrade to M10+, switch to VPC peering with Vercel and drop 0.0.0.0/0.
  • Do not try to maintain a hand-curated list of Vercel egress IPs — it drifts and the site will go down.

1.4 Get the connection string

  1. Connect → Drivers → Node.js.
  2. Replace <password> with the DB user password from step 1.2.
  3. Add ?retryWrites=true&w=majority (default from Atlas).
  4. This is your MONGODB_URI.

2. Vercel project setup

  1. Dashboard → Add New → Project → pick the Git repo.
  2. Framework preset: Next.js (auto-detected).
  3. Root directory: repo root (where package.json lives).
  4. Build command: npm run build (matches vercel.ts).
  5. Install command: npm install.
  6. Region: bom1 (Mumbai). Pinned in vercel.ts.
    • Why bom1: primary audience is India; lowest TTFB for the audience that matters. Trade-off: EU/US visitors take an extra ~150–300 ms. Add a second region (e.g. fra1) in vercel.ts if international orders grow.
  7. vercel.ts vs vercel.json: This project uses vercel.ts (the type-checked TS form via @vercel/config). Vercel reads it automatically when present. You do not need a vercel.json.

3. Environment variables

Set these in the Vercel dashboard (Settings → Environment Variables) for both Production and Preview environments unless noted.

3.1 Analytics IDs — Payload first, env-var fallback

GA4 ID and Meta Pixel ID are read from the Payload analytics-settings global at runtime. The env-vars above are fallbacks for the case where Payload is unreachable (build-time, DB outage). If both are set, Payload wins.

3.2 Preview auto-login

Set NODE_ENV=production on Preview env vars in addition to Production. The auto-login gate also checks VERCEL_ENV and CI.

4. First deploy

  1. Push to main. Vercel auto-builds.
  2. Watch the build logs in the Vercel dashboard.
  3. Once green, visit https://<project>.vercel.app/admin.
  4. Payload auto-creates indexes on first boot.

5. First admin user

Create the first admin via the Payload admin UI:

  1. Navigate to /admin.
  2. Create-first-user flow runs automatically on first visit.
  3. Use a real email + strong password. Store in 1Password.

6. Seed content

Two options:

  1. Payload admin UI (recommended for non-tech operators) — navigate to each collection and add records manually.
  2. Seed script — requires shell access: 
    MONGODB_URI=<prod-uri> PAYLOAD_SECRET=<prod-secret> npm run seed

    This populates sample mithai / QSR / snacks / merch / stories / karigars / farms / occasions records.

7. Analytics setup

  1. Log into Payload /admin.
  2. Open Globals → Analytics Settings.
  3. Paste GA4 ID (G-XXXXXXX) and Meta Pixel ID.
  4. Save. The site picks them up on next render — no rebuild needed.

8. Troubleshooting

Build fails on npm ci

Lockfile out of sync. Local run:

npm install --package-lock-only
git add package-lock.json
git commit -m "chore: resync lockfile"
git push

Build fails on tsc / lint

Don't bypass with --no-verify. Run locally:

npm run lint && npx tsc --noEmit

Fix errors, commit, push.

/admin returns 500

  • Check MONGODB_URI is set in the active environment.
  • Check Atlas IP allowlist includes 0.0.0.0/0.
  • Check database user password matches the connection string.

Lead form does not email

  • Check RESEND_API_KEY set + domain verified in Resend dashboard.
  • Check LEADS_INBOX set to a real inbox.
  • Inspect function logs in Vercel → Functions tab.

ISR not purging on Payload publish

  • Check REVALIDATE_SECRET matches in both Vercel env vars and Payload global.
  • Function logs should show revalidate hits.
