2 · Register the Razorpay webhook needs your Razorpay login

Payments already work — client-side verification plus the reconcile cron covered a real ₹2,258 test payment end-to-end. The webhook is belt-and-suspenders: server-to-server confirmation so payments are marked even if a buyer closes the browser mid-redirect.

  1. Get the secret that's already configured on the server (its local copy was purged for hygiene — read it straight from the VPS, don't write it down anywhere else). On this Mac's terminal: ssh hermes-vps 'sudo -iu mithai grep RAZORPAY_WEBHOOK_SECRET /opt/mithai-shop/.env' Copy just the value after =.
  2. Open the Razorpay Dashboard → Settings → Webhooks → Add New Webhook.
  3. Fill in:
    • Name: mishran-prod (anything you like)
    • Active URL: https://mishran.pranavb.com/api/webhooks/razorpay
    • Secret: paste the value from step 1
    • Events: tick payment.captured and payment.failed (add order.paid too if the dashboard offers it)
  4. Click Create Webhook. If it offers "Send test webhook", fire it — the endpoint logs and ignores unsigned test pings safely.

Note on Razorpay's API

We tried to register this programmatically for you; Razorpay's webhook-creation API has been erroring dashboard-side, which is why this is a manual step. If the dashboard also refuses, send Claude the exact error text.

Done when

The webhook is listed as Active. Tell Claude — verification is a one-liner on our side: place any TEST payment and check the payments record's rawWebhookEvents array has started filling.

3 · Enable UPI on the Razorpay account needs your Razorpay login

The UPI checkout rail is built and shipped on web, iOS, and Android ("UPI — GPay / PhonePe / BHIM"). It can't transact until UPI is enabled as a payment method on the account itself. Until then the rail is honest UI on top of a closed door.

  1. In the Razorpay Dashboard, go to Settings → Payment Methods.
  2. Under UPI, make sure it is enabled for the account (toggle on; some accounts see per-method sections — UPI should not be greyed out or restricted).
  3. If UPI is missing or locked, it's an account-level restriction — raise it from Settings → Support / Contact Razorpay ("enable UPI collections"). Test accounts sometimes need this flipped by Razorpay support.

Done when

A checkout in TEST mode offers UPI and completes with a test VPA (Razorpay's test docs list the success VPA like success@razorpay). Then the rail is live on all three surfaces with no further code changes.

4 · MSG91 real keys + SMS templates needs your MSG91 login

Today OTPs work only for a small bypass list of phones, and the order-confirmed SMS silently fails because no template is registered. The sending code is done and adapter-tested; it needs real credentials and template IDs.

Step A — check DLT status (the long pole)

Indian transactional SMS requires DLT-registered templates. If your MSG91 account already has DLT done, registering these takes minutes; if not, DLT approval itself can take a few days — start here first.

Step B — register these five templates

In MSG91, create transactional templates matching these texts (wording can be adjusted to taste — what matters is that you get a template ID for each):

PurposeSuggested textEnv var the ID lands in
Login OTPYour Mishran login code is ##code##. It expires in 10 minutes.MSG91_TEMPLATE_OTP
Order confirmedOrder ##order## confirmed at Mishran. We'll message you when it ships.MSG91_TEMPLATE_SMS_CONFIRMED
DispatchedOrder ##order## from Mishran has been dispatched.MSG91_TEMPLATE_SMS_DISPATCHED
Out for deliveryOrder ##order## from Mishran is out for delivery today.MSG91_TEMPLATE_SMS_OUT_FOR_DELIVERY
DeliveredOrder ##order## from Mishran was delivered. Thank you!MSG91_TEMPLATE_SMS_DELIVERED

Small correction

The repo's .env.example mentions MSG91_TEMPLATE_ORDER_STATUS — that name is stale. The live names are the four MSG91_TEMPLATE_SMS_* vars above (wired in lib/config.ts); the example file will be fixed when keys land.

Step C — hand over three things

  1. The auth key (Settings → API keys in MSG91) → becomes MSG91_AUTH_KEY.
  2. The sender ID (6-character DLT header) → MSG91_SENDER_ID.
  3. The five template IDs from step B.

Claude then sets them on the VPS .env, restarts, and — per the deployment doc — strips the OTP_BYPASS_PHONE / OTP_BYPASS_CODE test seams, so every login is a real SMS from that point. Verification: an OTP to any real phone arrives by SMS, and a fresh order triggers the confirmed text.

5 · Resend: API key + domain needs a Resend account

Lead notifications and abandoned-cart emails currently no-op silently. The code sends from hello@mishran.shop and leads@mishran.shop through Resend — the domain just needs verifying and a key set.

  1. Create/sign in at resend.com.
  2. Domains → Add Domain → enter mishran.shop.
  3. Resend shows DNS records (a TXT for ownership, plus SPF/DKIM entries). Add them at your DNS provider (wherever mishran.shop's nameservers live — same place the site's A record was set). If you don't manage DNS yourself, send Claude the record list and we'll tell you exactly what to paste where, or apply them if the DNS is on the VPS.
  4. Back in Resend, click Verify — usually green within minutes once DNS propagates.
  5. API Keys → Create API Key, full access, name it mishran-prod. Hand the key to Claude → RESEND_API_KEY on the VPS.

Done when

Domain shows Verified in Resend, and the next merch/wedding enquiry on the site delivers a notification to the ops inbox. Claude verifies with a live enquiry + a test abandoned-cart run.

6c · Karigar + lead-time data (provenance)

Product pages on all three platforms have a provenance block — who made it, freshness, shelf life — that stays hidden until products carry the data. Filling it is pure admin work:

  1. In admin, open Mithai Products (catalogue group).
  2. First add your karigars once: Karigars collection → add name (+ photo/blurb if you like). Even one entry — "Mishran kitchen", named lead confectioner — is enough to start.
  3. Open a product → the Karigar relationship field → pick one; set Lead time (e.g. "Made fresh daily" or "2 days notice"). Publish.
  4. Repeat for flagship products. The provenance rows appear on the web PDP immediately (≤60 s cache) and in both apps on next launch. Products left blank simply keep hiding the block — no rush to do all 91.

Why this matters

The trust strip and provenance rows shipped today on Android (and already on iOS/web) — this data is what makes them light up.
